================================================================================
Geant4 빌드·버전 확인 & API 메모 (Trigger 레포용)
================================================================================
목적: cmake/컴파일이 실제로 어떤 Geant4를 물고 있는지 확인하고, 지오 코드에서
      부모 물리볼륨 포인터를 다룰 때 헷갈리지 않도록 정리한다.
작성: 레포 유지보수 참고용. 공식 문서는 항상 설치된 G4 헤더·Book for Application
      Developers를 우선한다.

--------------------------------------------------------------------------------
1) 빌드가 쓰는 Geant4 확인 (권장 순서)
--------------------------------------------------------------------------------

(1) CMake 구성 직후 출력
    빌드 디렉터리에서:
      cmake ..   (또는 이미 구성된 경우)
    출력에 다음이 보이는지 확인:
      - Geant4_DIR
      - Found Geant4 ...
      - Geant4 version ...

(2) CMake 캐시에서 확인
      build/CMakeCache.txt 를 연다.
      검색 키워드:
      - Geant4_DIR
      - Geant4_VERSION  (또는 유사 항목)
      실제로 뽑힌 줄 저장본:
        _G4_version_release/cmake_geant4_cache_list.txt

(3) 링크되는 라이브러리 확인 (선택)
      빌드된 CBDsim 링크 라인 또는:
      ldd build/CBDsim/CBDsim   (실행 파일 경로는 환경에 맞게)
    Geant4 .so 경로가 cvmfs/로컬 중 어디인지 보면, 헤더와 라이브러리 불일치 여부를
    의심할 수 있다.

(4) 컴파일러가 실제로 포함하는 헤더 (문제 시)
      g++ -E -v ... 로 include 경로를 보거나,
      전처리된 결과에서 G4Version.hh 등 경로를 확인한다.

주의: "우리는 11.2를 쓴다"는 팀 합의와, "이 바이너리가 11.2 헤더로 빌드됐다"는
      별개다. 릴리스 노트(geant4_11.2_release_note.txt)는 기능·변경 요약이고,
      위 절차는 **현재 빌드의 단일 기준**을 잡는 데 쓴다.

--------------------------------------------------------------------------------
2) 부모(mother) 물리볼륨 — 기하 vs C++ API
--------------------------------------------------------------------------------

- 기하학적으로: 월드 밑이 아니면 **항상** 어머니 물리볼륨이 있다. "정의가 안
  되어 있다"기보다, **코드에서 부모 포인터를 어떻게 얻느냐**가 문제였다.

- G4VPhysicalVolume: 버전/클래스에 따라 GetMother() 등이 **없을 수 있다**.

- G4PVPlacement: GetMotherPhysical() 같은 멤버가 **문서·버전마다 다르거나**,
  컴파일러가 GetMotherLogical만 제안하는 경우가 있다. Border surface 등에
  **물리 볼륨 쌍**이 필요하면 논리 볼륨만으로는 부족할 수 있다.

- 실무 대안 (본 레포 CBDsimDetectorConstructionProto.cc에서 사용):
  부모를 "조회"하지 않고, **이미 보유한 어머니 물리볼륨 포인터(envPhysT1/T2 등)에서
  자식 이름으로 DFS** 하여 LG 등을 찾는다. 이렇게 하면 부모 getter API 차이에
  덜 의존한다.
